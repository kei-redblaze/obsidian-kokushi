# Kokushi

Kokushi は、試験の過去問や模擬試験の問題を、Obsidian の Vault で演習するプラグインです。出典や解答状況で出題範囲を絞り、採点結果を記録しながら問題ごとにメモや知識ノートを残せます。

## インストール

Obsidian 1.7.2 以降に対応しています。

1. GitHub Releases から `main.js`、`manifest.json`、`styles.css` をダウンロードします。[GitHub Releases](https://github.com/kei-redblaze/obsidian-kokushi/releases/latest)
2. Vault の `.obsidian/plugins/obsidian-kokushi/` に3ファイルを置きます。フォルダーがなければ作成します。
3. Obsidian を開き直し、**設定 → コミュニティプラグイン** で **Kokushi** を有効にします。
4. [問題セットの形式](#問題セットの形式)に沿って Vault に問題を配置し、コマンドパレットで **Kokushi: 演習を開く** を選びます。

## 演習と復習

- 出題範囲では **出典**、**出題順序**、**出題対象**、**出題問題数** を選べます。出題対象の **正解**・**不正解**・**未解答** は組み合わせて指定できます。採点除外問題は、解答履歴がなければ未解答、履歴があれば正解の出題対象に含まれます。
- **解答・採点** を押すと正誤と正答が表示されます。**わからない** を選んで採点することもできます。**コピー** は問題番号・問題文・選択肢をテキストとしてコピーします。正答と画像はコピー対象外です。
- **出題範囲の選択に戻る** で中断した演習は、出題範囲画面の **未完了の演習 → 詳細 → 再開** から続けられます。
- **演習を終了する** と結果が表示されます。**同じ問題でもう一度** で全問、**間違えた問題を復習** でその回の不正解と未採点の問題を、元の順番で演習できます。

## ダッシュボードと履歴

コマンドパレットの **Kokushi: ダッシュボードを開く** で、学習進捗、正答率、日別推移、演習履歴、解答履歴を確認できます。履歴は各5件まで表示し、6件以上ある場合は **すべて表示** で一覧を開けます。

演習履歴の状態ボタンから詳細を開くと、問題ごとの解答と採点結果を確認できます。中断した演習は **再開** で続行でき、完了済みの演習も未採点の問題があれば再開できます。完了済みの詳細では **このセットで再演習** で当時の全問を新しい演習として開始できます。**この回の誤答を再演習** は、採点結果が不正解だった問題が対象です。

**演習履歴を破棄** の確認画面では、初期状態で演習履歴だけを削除します。**この回の解答履歴も削除する** にチェックを入れると、その回の解答も削除され、ダッシュボードの集計から外れます。

## メモと関連ノート

- 採点後のメモ欄に複数行のメモを入力できます。入力が止まったときや欄を離れたときに自動保存されます。
- 採点後の **ノート → 新規** で `02_Notes/` にノートを作成し、問題に関連付けます。**編集** から既存ノートの追加や関連付けの解除ができます。複数の問題に同じノートを関連付けられます。
- 関連ノートはリンクから別ペインで開き、スマートフォンでは別タブで開きます。Obsidian 内で `02_Notes/` 配下のノートを改名・移動すると、関連付け先も更新されます。

## 問題セットの形式

v1.1では、問題セットをMarkdownと画像で配布できます。1問につき1つの `.md` ファイルに、問題文・選択肢・正答を記述します。

```text
<Vault>/
├── 01_Questions/
│   ├── 国試120回/
│   │   ├── 120A37.md
│   │   └── images/
│   │       └── 120A37-01.jpg
│   └── A社冬模試/
│       └── 001.md
├── 02_Notes/
│   └── 関連知識ノート.md
└── 03_Data/
    ├── Attempts/
    │   ├── attempts.jsonl
    │   └── sessions/
    └── YAML/
        └── A社冬模試/
            └── 001.yaml
```

`01_Questions/` 直下に出典ごとのフォルダーを置きます。ZIPで受け取った場合は展開し、各出典フォルダーを `01_Questions/` 直下に配置します。出典フォルダー名は「出典」、ファイル名から拡張子を除いた部分は「問題番号」に表示されます。`001` の先頭ゼロは保持されます。同じ出典内では、分野別のサブフォルダーに分けた場合も問題番号を一意にします。別の出典なら同じ番号を使えます。

### 問題文・選択肢・正答

以下は書式を示すための `001.md` の例です。

```markdown
## Question

該当するものをすべて選べ。

## Options

a. 選択肢A
b. 選択肢B
c. 選択肢C

## Answer

a. 選択肢A

a. 選択肢A
b. 選択肢B
```

- `## Question` の下に問題文を記述します。Markdownの表や画像を含められます。画像は `![説明](./images/画像.jpg)` のように問題ファイルからの相対パスで参照します。連続する画像は演習画面で横並びになります。
- 選択式では `## Options` の下に `a. 選択肢の本文` の形式で選択肢を記述します。記号には半角英小文字を使います。数値入力では `## Options` を省略します。
- `## Answer` の見出しは必須です。選択式では `## Options` の該当行を転記します。行頭の記号が採点に使われ、後ろの本文は確認用です。
- 見出しは大文字・小文字を含めて固定です。各セクションは次の `#` または `##` 見出しで終わります。本文中の小見出しには `###` 以降を使います。
- **空行で別の正答候補に分かれ、空行で区切られていない行は1つの組み合わせ**になります。周囲の空行は無視します。例では「aのみ」と「aとbの両方」が正答です。

### 解答形式の判定

| `## Answer` の記述 | 出題・採点 |
| --- | --- |
| すべての候補が1項目 | 単一選択。候補のうち1つを選べば正解です。 |
| すべての候補が同じ数の複数項目 | 複数選択。必要な選択数を画面に表示します。 |
| 候補によって項目数が異なる | 複数選択。選択数は固定せず、1つ以上選べば採点できます。 |
| 半角数字だけを1候補につき1行 | 数値入力。候補が複数ある場合は空行で区切ります。文字列の完全一致で採点するため、`012` と `12` は別の解答です。 |
| 空欄、または `採点除外` の1行だけ | 採点除外。`## Options` があれば選択数を固定しないチェックボックス、なければ数値入力欄を表示します。 |

選択式では選択順を問わず、いずれかの候補と完全に一致すれば正解です。存在しない選択肢の指定、同じ候補内での記号の重複、数値と選択肢の混在、`## Answer` の欠落は書式エラーになります。ファイル名と理由は読み込み時に通知します。

AIで問題を生成する場合も同じ書式を使います。正答を転記するときは、候補の内部に空行を入れず、候補の間だけ空行を入れます。意図的な採点除外は `採点除外` と明記してください。

## データの保存場所

| データ | Vault内の保存場所 |
| --- | --- |
| 問題文・選択肢・正答・画像 | `01_Questions/` |
| 関連ノートの本文 | `02_Notes/` |
| 選んだ解答と採点結果 | `03_Data/Attempts/attempts.jsonl` |
| 出題順・演習の進行状況・採点結果 | `03_Data/Attempts/sessions/` |
| 問題ごとのメモ・関連ノートへのリンク | `03_Data/YAML/<出典>/<問題番号>.yaml` |

YAMLはメモや関連ノートを初めて保存したときに作成します。正答は問題Markdownの `## Answer` で管理します。正答を訂正すると次回の採点から反映され、過去の履歴には当時の採点結果が残ります。問題文や入力形式も変更した場合は、更新された問題を表示して解答をやり直せます。

v1.1はこの構成で動作します。v1.0.7以前の問題別YAMLによる採点、既存の履歴やメモの移行には対応していません。

## 開発・リリース

GitHub Actions と同じ Node.js 24 を使う場合の手順です。

```bash
npm ci
npm run build
npm run lint
```

`npm run dev` で変更を監視し、`main.js` を再ビルドできます。動作確認する場合は、生成された `main.js` と `manifest.json`、`styles.css` をテスト用 Vault のプラグインフォルダーに配置します。

リリース時は `npm version <新しいバージョン> --no-git-tag-version` でバージョンを更新し、変更を `master` に反映します。`manifest.json` のバージョンが最新タグより新しい場合、GitHub Actions がビルドし、バージョンと同名のタグを作成して3ファイル付きのリリースを公開します。
