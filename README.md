# Kokushi

Kokushi は、医師国家試験の過去問や模擬試験の問題を、Obsidian の Vault で演習するプラグインです。出典や解答状況で出題範囲を絞り、採点結果を記録しながら問題ごとにメモや知識ノートを残せます。

## インストール

Obsidian 1.7.2 以降に対応しています。

1. GitHub Releases から `main.js`、`manifest.json`、`styles.css` をダウンロードします。[GitHub Releases](https://github.com/kei-redblaze/obsidian-kokushi/releases/latest)
2. Vault の `.obsidian/plugins/obsidian-kokushi/` に3ファイルを置きます。フォルダーがなければ作成します。
3. Obsidian を開き直し、**設定 → コミュニティプラグイン** で **Kokushi** を有効にします。
4. 問題セットを Vault の `01_Questions/` に配置し、コマンドパレットで **Kokushi: 演習を開く** を選びます。

## 演習と復習

- 出題範囲では **出典**、**出題順序**、**出題対象**、**出題問題数** を選べます。出題対象の **正解**・**不正解**・**未解答** は組み合わせて指定できます。採点除外問題は、解答履歴がなければ未解答、履歴があれば正解の出題対象に含まれます。
- **解答・採点** を押すと正誤と正答が表示されます。**わからない** を選んで採点することもできます。**コピー** は問題番号・問題文・選択肢をテキストとしてコピーします。
- **出題範囲の選択に戻る** で中断した演習は、出題範囲画面の **未完了の演習 → 詳細 → 再開** から続けられます。
- **演習を終了する** と結果が表示されます。**同じ問題でもう一度** で全問、**間違えた問題を復習** でその回の不正解と未採点の問題を、元の順番で演習できます。

## ダッシュボードと履歴

コマンドパレットの **Kokushi: ダッシュボードを開く** で、学習進捗、正答率、日別推移、演習履歴、解答履歴を確認できます。履歴は各5件まで表示し、6件以上ある場合は **すべて表示** で一覧を開けます。

演習履歴の状態ボタンから詳細を開くと、問題ごとの解答と採点結果を確認できます。中断した演習は **再開** で続行でき、完了済みの演習も未採点の問題があれば再開できます。完了済みの詳細では **このセットで再演習** で当時の全問を新しい演習として開始できます。**この回の誤答を再演習** は、採点結果が不正解だった問題が対象です。

**演習履歴を破棄** の確認画面では、初期状態で演習履歴だけを削除します。**この回の解答履歴も削除する** にチェックを入れると、その回の解答も削除され、ダッシュボードの集計から外れます。

## メモと関連ノート

- 採点後のメモ欄に複数行のメモを入力できます。入力が止まったときや欄を離れたときに自動保存されます。
- 採点後の **ノート → 新規** で `03_Notes/` にノートを作成し、問題に関連付けます。**編集** から既存ノートの追加や関連付けの解除ができます。複数の問題に同じノートを関連付けられます。
- 関連ノートはリンクから別ペインで開き、スマートフォンでは別タブで開きます。Obsidian 内で `03_Notes/` 配下のノートを改名・移動すると、関連付け先も更新されます。

## 問題セットの形式

1つの出典を1つのフォルダーにまとめ、`01_Questions/` の直下に配置します。1問につき、問題文の `.md` と採点情報の `.yaml` を、拡張子以外が同じ名前で同じフォルダーに置きます。

### フォルダー構成

```text
<Vault>/
└── 01_Questions/
    ├── 第120回医師国家試験/
    │   ├── 120A37.md
    │   ├── 120A37.yaml
    │   └── images/
    │       ├── 120A37-01.jpg
    │       └── 120A37-02.jpg
    └── 模擬試験A/
        ├── 001.md
        ├── 001.yaml
        ├── Q2.md
        └── Q2.yaml
```

- `01_Questions/` 直下のフォルダー名が「出典」に表示されます。出典の中は分野などでサブフォルダーに分けられます。`01_Questions/` に直接置いた問題は「フォルダ直下」にまとまります。
- 問題は出典と問題番号の組み合わせで識別します。異なる出典に同じ `001` を置けます。同じ出典内で番号が重複すると、該当する問題は読み込まれません。配布後に出典フォルダー名や問題番号を変えると、既存の履歴との対応が切れます。
- ZIP で配布する場合は、展開して各出典フォルダーを `01_Questions/` 直下に置きます。複数の出典をまとめる場合も、配布用の外側フォルダーから取り出して各出典を配置します。

### 問題文 Markdown

以下は書式を示すための `120A37.md` の記述例です。

```markdown
## Question

65歳の男性。労作時呼吸困難を主訴に来院した。
胸部エックス線写真と胸部CT画像を示す。最も考えられる疾患はどれか。

![胸部エックス線写真](./images/120A37-01.jpg)
![胸部CT画像](./images/120A37-02.jpg)

## Options

a. 肺気腫
b. 肺水腫
c. 気胸
d. 肺塞栓症
e. 胸膜中皮腫
```

- 問題文は `## Question` の下に書きます。Markdown の表や画像を含められます。
- 選択式の問題は `## Options` の下に、`a. 選択肢の本文` のように半角英小文字、ピリオド、空白で始めます。記号は問題内で重複させず、YAML の正答に使う記号とそろえます。数値入力の問題では `## Options` を省略できます。
- 見出しは大文字・小文字を含めて `## Question` と `## Options` で固定です。各セクションは次の `#` または `##` 見出しで終わるので、本文中の小見出しには `###` 以降を使います。
- 画像は問題 Markdown からの相対パスで参照し、ファイル名の大文字・小文字もそろえます。問題文に画像を連続して置くと、演習画面で横並びになります。

### 採点 YAML

上の例に対応する `120A37.yaml` は以下のとおりです。

```yaml
id: "120A37"
type: single
answer:
  - ["a"]
```

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `id` | 必須 | Markdown と YAML の共通ファイル名から拡張子を除いた問題番号です。`"120A37"`、`"001"`、`"Q2"` のように引用符で囲みます。 |
| `type` | 必須 | `single`（単一選択）、`multiple`（複数選択）、`numeric`（数値入力）のいずれかです。 |
| `answer` | 必須 | 正答の組み合わせを並べた二重配列です。内側の配列1つが正答1通りです。 |
| `excluded` | 任意 | `true` で採点除外となります。省略または `false` で通常どおり採点します。採点除外問題に正答を指定しない場合も `answer: []` を記述します。 |

| 問題形式 | `answer` の例 | 採点の扱い |
| --- | --- | --- |
| 単一選択 | `[["a"], ["c"]]` | `a` と `c` のどちらか一方を選ぶと正答です。 |
| 複数選択 | `[["a", "c"], ["b", "d"]]` | `a` と `c`、または `b` と `d` の組み合わせが正答です。選択順は問いません。各組み合わせは重複のない2個以上の記号で、個数をそろえます。 |
| 数値入力 | `[["12"]]` | 半角数字 `0`〜`9` だけを入力でき、文字列の完全一致で採点します。`"012"` と `"12"` は別の解答です。 |

## データの保存場所

| データ | Vault 内の保存場所 |
| --- | --- |
| 問題文・採点情報・画像 | `01_Questions/` |
| 演習セッション | `02_Attempts/sessions/` |
| 問題ごとの解答記録 | `02_Attempts/attempts.jsonl` |
| 関連ノートの本文 | `03_Notes/` |
| 問題ごとのメモ・ノートへのリンク | 各問題の YAML の `memo` と `relatedNotes` |

メモは文字列として保存します。`memo` と `relatedNotes` は問題セット作成時に省略できます。出典を持たない v1.0.6 以前の履歴は、元のファイルに残ります。v1.0.7 以降の履歴表示と集計の対象は、出典を持つ新形式です。

## 開発・リリース

GitHub Actions と同じ Node.js 24 を使う場合の手順です。

```bash
npm ci
npm run build
npm run lint
```

`npm run dev` で変更を監視し、`main.js` を再ビルドできます。動作確認する場合は、生成された `main.js` と `manifest.json`、`styles.css` をテスト用 Vault のプラグインフォルダーに配置します。

リリース時は `npm version <新しいバージョン> --no-git-tag-version` でバージョンを更新し、変更を `master` に反映します。`manifest.json` のバージョンが最新タグより新しい場合、GitHub Actions がビルドし、バージョンと同名のタグを作成して3ファイル付きのリリースを公開します。
